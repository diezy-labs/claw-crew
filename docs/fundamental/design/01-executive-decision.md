## 1. Executive Decision

Fleet AI should not present itself as a dense agent administration console on first launch. The existing application already has broad operational capability—chat, agents, tasks, SOPs, cron, tools, integrations, runs, approvals, audit, logs, metrics, provider health, sessions, recovery, and diagnostics—but its current page inventory is closer to a technical control console than the intended **Pirate King → Quartermaster → Fleet → Ship → Quest → Artifact → Treasure** product experience.

The recommended UX direction is:

> **Conversation-first at the entry point, operations-first in the workspace, and technical depth on demand.**

The main screen becomes **Quartermaster Office**: an executive workbench where the Owner can chat, view the most important Fleet status, see decision requests, launch or create Quests, and inspect Artifact outcomes. Mission Board, Ships, Artifacts, Treasury, and Logbook become the primary product surfaces. Existing technical pages remain valuable but move behind an advanced **Fleet Control** area.

The visual tone should borrow the strongest interaction patterns—not the literal visual language—from Kiro Crew, Claude Desktop, and ChatGPT Desktop:

- **Kiro-like:** persistent work, clear task/routine visibility, desktop continuity, agent autonomy made inspectable.
- **Claude-like:** calm editorial readability, strong conversational focus, generous whitespace, high-quality artifact presentation.
- **ChatGPT-like:** low-friction command input, familiar chat behavior, quick actions, simple information hierarchy.
- **Fleet-specific:** maritime/pirate narrative through terminology, iconography, progress semantics, and carefully controlled accent details—not through cartoon visuals or game-like clutter.

The product should feel like a premium command room, not a pirate game and not a DevOps dashboard.
